# Ares 4.0.8

Stable patch release `4.0.8+3064`. ABI split codes `30641` (armeabi-v7a),
`30642` (arm64-v8a) and `30643` (x86_64), each above the highest published
4.0.7 split (`30633`). The production package `com.hermesagent.hermes_android`
and signing certificate are unchanged; install over the existing app.

## Fixed

### NextGen reads replies aloud and copies code blocks in one tap (#289, fixes #288)

NextGen had no TTS at all while Classic offered Read aloud on every assistant
reply, and copying one fenced block meant discovering a small icon or dragging
a selection across the fence — a regression for anyone who switched interfaces.

- Every completed assistant reply's action row now offers **Read aloud**, which
  becomes **Stop** while that reply is being read. Streaming replies get the
  action once they are final.
- One shared playback engine per chat view (`NgReadAloud`): starting a reply
  stops whichever reply was being read, claims are serialized so two quick taps
  cannot interleave, and only one Stop is shown at a time. Switching chats, or a
  retry/history reload that removes the reading reply, stops playback.
- Voice selection mirrors Classic (`voice_name`/`voice_locale` preferences,
  speech rate 0.48), applied best-effort so a missing voice degrades to the
  engine default. Playback failure surfaces the existing "Read aloud is
  unavailable on this device" toast.
- Android uses the same completion-correlated `FlutterVoiceReplySpeaker` as
  Classic hands-free: long replies are chunked to the engine's input limit and
  Stop is a real playback barrier. Other platforms use generation-guarded
  completion/cancel/error side channels, including a one-shot swallow for a
  stopped utterance's late cancel.
- Starting read aloud stops active dictation, matching Classic's
  settle-before-playback contract.
- Fenced code blocks in NextGen render a labelled **Copy code** button (larger
  tap target, one obvious tap) that copies exactly that block's source. The
  control is wrapped in `Flexible` so long localized labels ellipsize instead
  of overflowing at narrow widths / large text scales. Classic keeps its
  icon-only header unchanged.
- `ng_read_aloud` is localized in all 12 locales; Stop reuses `ng_stop`.

Reported by [@Susensio](https://github.com/Susensio) on behalf of a user, with
a source-level comparison against Classic. The per-block copy control already
existed and copied the exact fence source (covered by tests); the labelled
button makes it discoverable. The exact on-device failure mode was not
reproducible from source alone — device confirmation after publication is
welcome on #288.

## Install

Download the APK for your device from the release assets and install over the
existing app; do not uninstall or clear app data. The Google Play build
updates through Play.

## Verification

- `flutter analyze --no-pub --fatal-infos`: no issues.
- 21 new tests in `test/nextgen_read_aloud_test.dart`: claim/stop/switch races,
  failure and prepare-failure recovery, voice preferences, dispose, non-Android
  side channels (including the late-cancel swallow), the streaming gate,
  chat-switch stop, labelled-copy clipboard exactness, a 280dp + text scale 3.0
  overflow guard, and Classic's icon-only header unchanged.
- The full Flutter test suite and the Play distribution tests pass on the
  release head, including the Classic select-text drag regression that guarded
  the code-block header change.
- A focused diff review approved the design; its three hardening suggestions
  (late-cancel swallow, dictation settle, overflow protection) are implemented.
- Release APKs are production-signed and verified against the established
  certificate, package, ABI and version-code gates by the release workflow.
