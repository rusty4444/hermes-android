## Integrated OAuth behaviour

**More → Usage → Provider sign-in** and **Settings → Provider sign-in** use the
saved Dashboard transport. The audited host catalog supports device-code login
for **Nous, OpenAI Codex, MiniMax and xAI**. Anthropic is external-only, requiring
host-side setup; OpenRouter is absent from this OAuth catalog. API-server and
Desktop RPC transports do not support this flow. Provider names in Usage are
not an OAuth support list. No guessed callback or manual-code endpoint is used.

An explicit tap opens a validated HTTPS provider page in an external browser,
without Dashboard headers or client identity. Device codes/session identifiers
are transient route memory; provider tokens remain on the host. Discovery,
start, poll, cancellation and catalog readback preserve saved origin/mount prefix,
selected profile, authentication and mTLS and reject redirects. Lifecycle fences
ignore late responses after disposal/profile replacement; cancellation uses the
captured old authority. Cancellation failure remains uncertain, not confirmed.

Approval displays **Approval received; account verification unavailable**, never
**Signed in as**. Approved session A can still report A after host account B
replaces it; catalog `logged_in` establishes credential availability, not current
identity. There is no authoritative current-account endpoint in this contract.
Completion clears codes/timers and does not re-poll historical identity. Only the
same-profile redirect-rejecting OAuth catalog is refreshed after approval; no
automatic generic model/analytics refresh or model/config write is added.
Catalog failure does not turn received approval into login failure. If catalog
loading fails, close and reopen the sign-in screen to reload it; there is no
in-screen catalog retry action. Nous free-tier replacement may itself change host
defaults; the app warns rather than promising token-only host side effects.

See [OAuth contract and safety](../provider-oauth.md) and
[current-account correction evidence](../provider-oauth-readback-verification.md).

## Usage and localisation

Usage separates Hermes-recorded activity/model analytics from host-reported
account allowances. Only reported five-hour/session and weekly windows,
percentages and reset timestamps appear. Unknown window labels remain unchanged;
missing values are unavailable, not zero or unlimited. Accounts remain separate,
not averaged; no token budgets, balances, prices or entitlements are invented.
Codex access is distinct from paid OpenAI API access; Claude OAuth allowance is
distinct from paid Claude API billing. See [usage boundaries](../provider-usage.md).
All 11 shipped ARB locales retain translations for all 32 OAuth and 15 quota keys,
including regional variants; the unused verified-account key is not rendered as
an account-verification claim.
