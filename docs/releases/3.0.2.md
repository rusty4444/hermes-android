# Hermes Android 3.0.2

Version **3.0.2+3006** fixes a stale recovery view that could leave an existing chat at an older reply despite newer saved messages. This page covers changes since **3.0.1**, including the fixes tested in **3.0.2-recovery.1**.

[Download 3.0.2](https://github.com/rusty4444/hermes-android/releases/tag/v3.0.2) · [Changes since 3.0.1](https://github.com/rusty4444/hermes-android/compare/v3.0.1...v3.0.2) · [Changelog](../../CHANGELOG.md)

## Upgrading

Export an encrypted configuration backup before updating, and keep its password safe. Backups can include connection credentials and imported client private keys. Install the matching production-signed APK over your existing app. **Do not uninstall or clear app data.**

The package remains `com.hermesagent.hermes_android`, with the existing production signing identity.

| APK | Device | Version code |
| --- | --- | --- |
| `app-arm64-v8a-release.apk` | Most current Android phones/tablets | `30062` |
| `app-armeabi-v7a-release.apk` | Older 32-bit ARM devices | `30061` |
| `app-x86_64-release.apk` | x86_64 Android devices/emulators | `30063` |

Base build `3006` puts every stable split above the highest 3.0.2-recovery.1 code, `30053`, and all 3.0.1 splits. This lets testers upgrade in place. Older APKs have lower version codes; a downgrade can require uninstalling and restoring a backup. Debug builds use a separate package and Android debug signer.

## Existing chats and saved history

After a turn lost its final confirmation, the app could retain an older received reply after newer saved messages. The end action could then land on that old reply, making the chat appear frozen even after Refresh.

The app now separates eligible retained unknown output from the saved-history view. Refreshed saved history opens at its newest visible message. The **Saved history** end action takes you to the saved end, while delayed reads respect newer scrolling and navigation choices. A failed or empty history read does not hide retained output.

New live prompts, tools and replies keep their existing presentation. The app does not change saved messages, infer correspondence from matching prose or row numbers, or resend a request to fill an apparent gap.

## Inspecting retained output

Tap **Received · match unconfirmed** above the transcript to open a separate, read-only inspector. You can read retained public output without moving the saved transcript or editing, retrying or resubmitting a prompt.

The inspector owns its scroll and detail state. Tool and reasoning expansion choices survive lazy scrolling within that visit. Separate storage for expansion state and scroll offsets avoids the earlier type-collision crash on remount.

Quiet mode keeps its existing completed-reply filtering. Enable **Verbose Mode** to inspect retained public details. Unknown outcomes remain unknown: an idle gateway or partial reply does not prove that a turn succeeded.

## Compatibility and delivery limits

- You do not need a backend patch, gateway restart or app-data reset for this fix.
- Saved history and received output retain independent provenance. The gateway's complete `persisted_turn` receipt and fresh physical history still govern proven saved/received handover. This release does not invent a match or promote an uncertain outcome to success.
- The app keeps received output in memory for the current application session, subject to existing retention limits. It can shorten or remove that output as limits apply. Closing the app or connection can lose it; the inspector is not a durable archive.
- Quiet mode still requires completion metadata for saved replies. Enable Verbose Mode when an older gateway lacks that metadata. This release does not claim to fix every possible connection, authentication or live-update fault.
- File previews, the 25 MiB transfer limit, encrypted backups and client-certificate handling retain their existing behaviour. See the [3.0.1 notes](3.0.1.md#compatibility-and-delivery-limits).
- Background notifications still need the separate, enabled and operator-authorised [mobile-push server companion](../mobile-push-server.md) and a supported phone transport. Updating the APK alone does not install host software.
