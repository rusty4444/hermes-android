# Ares 4.0.10

Stable patch release `4.0.10+3066`. ABI split codes `30661` (armeabi-v7a),
`30662` (arm64-v8a) and `30663` (x86_64), each above the highest published
4.0.9 split (`30653`). The production package `com.hermesagent.hermes_android`
and signing certificate are unchanged; install over the existing app.

## Fixed

### The NextGen chat list fills past cron-only pages (#298, fixes #297)

On a gateway with many scheduled jobs (~750 cron rows among ~1.4k sessions
in the report), the first activity-ordered pages were nothing but cron runs.
The chat list hides those rows, so the All list showed one or two
conversations with no scroll extent — and scroll-only paging never requested
page two. Search found the missing chats because it reads a different
endpoint.

- Refresh now reads bounded pages (up to 10 × 60 rows) until at least 20 chat
  rows are collected or the store ends. Cron rows with content are kept for
  the Crons section; untitled cron shells stay filtered.
- The raw server offset is tracked separately from the filtered list length.
  Load-more previously used the filtered row count as the server offset, so
  it re-read hidden shells instead of advancing; it now pages from the raw
  offset and applies the same shell filter, deduping by id.
- A short list gets an explicit **Load more** row: with no scroll extent,
  scroll-only paging cannot grow it.
- Search stays a single server-side read; no gateway change is required.

Reported by [@bruno-keeper](https://github.com/bruno-keeper) with measured
gateway evidence (55 of 60 first-page rows were untitled cron shells) and a
source-level diagnosis. New regressions cover cron-only first pages, the
bounded scan with load-more continuation, raw-offset paging with dedupe,
single-read search, and the Load more row; they fail on the unfixed tree.

### Clarify questions survive returning to a chat (#295)

A chat waiting on a `clarify` question showed the card in Hermes Desktop but
nothing in NextGen when the app returned to it. The catch-up resume
(`_reloadForCatchUp`) read only `session_id` and `running`, ignoring
`open_requests` — unlike the attach and catch-up paths. A client attaching
after the question was asked gets no live clarify frame, so the resume
replay is the only way to see it.

- The catch-up resume now delivers `open_requests` and binds them to the
  chat exactly like the attach path; the socket handler was extracted to
  `NextGenGateway.acceptServerRequest` without behaviour change.
- Verified against the real gateway resume producers (`open_requests` shape,
  flat `params.session_id`, clarify question fields); the loopback regression
  uses an anonymised real Hermes 0.23 resume reply and fails before the fix.

By [@manuelanguitatrejo](https://github.com/manuelanguitatrejo). Original
commits preserved via a true merge commit.

### Profile chooser after sign-in on gated gateways (#296, completes #292)

On a gated multiplexed gateway the unauthenticated `/api/status` probe hides
its profiles, so NextGen showed an empty chat list and offered no chooser.

- After sign-in, profiles are read from the authenticated `GET /api/profiles`
  when the probe had none, and the chooser is offered as a step before
  connecting (signing in again from an existing connection uses the same
  step).
- Preselect counts the chats NextGen lists per profile (page one, minus cron
  rows): if the default holds none and exactly one other profile holds some,
  that profile is chosen. Request shapes were verified against the real
  dashboard handlers; no new user-visible strings.
- Maintainer follow-up: leaving the profile step used to keep the pending
  choice, so backing out and signing in to another gateway showed the old
  chooser and could connect the old gateway. The pending choice is now
  cleared on back and on every new probe; a failed count read keeps the
  chooser; a server-removed saved profile falls back to the server default.
  A two-gateway loopback regression reproduces the defect on the pre-fix
  tree.

By [@manuelanguitatrejo](https://github.com/manuelanguitatrejo). Original
commits preserved via a true merge commit.

## Install

Download the APK for your device from the release assets and install over the
existing app; do not uninstall or clear app data. The Google Play build
updates through Play.
