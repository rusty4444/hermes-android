# Ares 4.0.7

Stable patch release `4.0.7+3063`. ABI split codes `30631` (armeabi-v7a),
`30632` (arm64-v8a) and `30633` (x86_64), each above the highest published
4.0.5 split (`30623`). The production package `com.hermesagent.hermes_android`
and signing certificate are unchanged; install over the existing app.

Covers all changes since 4.0.5, including the paging fix prepared under the
unpublished 4.0.6 tag (its release workflow failed the identity gate and no
4.0.6 APKs were published).

## Fixed

### Sending works against Hermes 0.23.x gateways (#286, fixes #285)

Hermes 0.23.0 began refusing a Desktop Gateway `prompt.submit` that carries no
`submission_id`/`input_id`: the admission check in
`AuthorityConnection.submission` (`gateway/session_controls.py`) raises a bare
`invalid_params` (wire code 4001) and logs nothing. Ares 4.0.5 and earlier sent
no such id, so every message over that transport failed with
"Not sent: invalid_params" on 0.23.x gateways, in new and existing chats, and
Retry failed the same way (upstream NousResearch/hermes-agent#151715).

Both send paths (`WsClient.submitPrompt` and the NextGen chat controller) now
mint a UUID `submission_id` for every turn. NextGen's Retry reuses the failed
send's id, so an ambiguous loss is answered by the gateway's idempotent replay
instead of a second turn; the classic path recovers ambiguous sends from
server history without resending. If a pre-0.23 gateway rejects the extra
field (`extra="forbid"` validation, wire code 4000 naming `submission_id`),
the send is retried once without it — after re-checking admission and socket
ownership — keeping older gateways working.

Reported with a source-level diagnosis by
[@shmuelsash](https://github.com/shmuelsash).

### NextGen paging carries growth overlap forward (#284, fixes #280)

After a burst of new rows beside a running turn, paging re-anchored on the
shown rows and re-fetched offsets full of rows already on screen; a live
turn's stored rows could also page back in as older duplicate items. Each
page's already-known rows now accumulate into a running shift so offsets
strictly increase, and at turn end the controller adopts the unknown stored
tail — for a turn of any length — and reconciles the shift, so paging resumes
at the exact coverage boundary even when the reader paged during the turn or
an adoption races an in-flight page. This removes the known limits recorded
in 4.0.5.

Contributed by [@Thaeland](https://github.com/Thaeland).

## Install

Download the APK for your device from the release assets and install over the
existing app; do not uninstall or clear app data. The Google Play build
updates through Play.

## Verification

- The full Flutter test suite passes, including a real loopback-WebSocket
  wire test for the legacy-gateway fallback and its admission re-check, unit
  tests for `submission_id` generation and NextGen retry reuse, and paging
  regressions asserting strictly increasing offsets across a growth burst,
  no re-inserted live-turn rows, no skipped rows when paging resumes after a
  turn ends, and full adoption of turns longer than five pages.
- The `prompt.submit` contract was checked against the Hermes 0.23.1 gateway
  source (allowed field set and admission check) and the pre-0.23
  `extra="forbid"` validation shape at tag `v2026.9.21`.
- Release APKs are production-signed and verified against the established
  signer SHA-256 `475baf43…f592fb`.

## Not verified

- No reproduction on the reporter's own 0.23.2 gateway or device; the fix is
  verified against the gateway source contract and loopback wire tests.
