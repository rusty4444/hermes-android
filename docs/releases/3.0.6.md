# Hermes Android 3.0.6

Version **3.0.6+3010** keeps API-server turns alive through backgrounding and
stops approval/input notifications from leaking command details. The production
package, signing identity, gateway requirements and saved conversation data
remain unchanged.

## Changes since 3.0.5

- API-server (REST `POST /v1/chat/completions` + SSE) sends now register as
  app-wide turn activity for the whole streaming lifetime, released when the
  stream settles. With **Keep chats active in the background** enabled, the
  foreground service can now engage for REST chats: backgrounding the phone
  mid-turn no longer freezes the process and destroys the turn on a dropped
  socket (#225, #226).
- Approval and input notifications show generic body text, so command and
  request details never appear on the lock screen. Titles still name the
  connection and session, and approve/deny actions and tap routing into the
  pending-request UI are unchanged. Connection attribution and state are
  spelled out, status/error/recovery controls sit next to the settings they
  affect, the disable action explains what it does and does not change, the
  silent verification step is labelled, and the switch is screen-reader
  accessible (#224).

## Upgrading

Export an encrypted configuration backup and keep its password safe. Install
the matching production-signed APK over the existing app without uninstalling
or clearing app data. Package `com.hermesagent.hermes_android` and the established
production signing certificate remain unchanged.

Base code `3010` yields `30101` for ARMv7, `30102` for ARM64 and `30103` for
x86_64, above every 3.0.5 split. Debug builds use the separate `.dev` package and
are not production upgrades.

## Compatibility and delivery limits

- No host patch, gateway restart, model-routing change or new server setting is
  required. Existing optional mobile-push companion prerequisites still apply.
- The REST keep-alive registration protects the turn while the stream is in
  flight; it does not survive force-stop, Doze or OEM background killers, and
  durable `/v1/runs` reattach on this transport remains tracked in #149.
- While the app is backgrounded the gateway connection is closed on purpose, so
  background events surface as encrypted kind-only push hints rather than
  notification detail.
- This release does not include the blocked long-paste or stock-idle settlement
  PRs. It adds no WebSocket execution-idempotency guarantee and never treats
  delivery uncertainty as permission to resend.
- Automated widget, owner, full-suite and CI gates do not certify physical-phone
  acceptance or universal gateway compatibility. Existing preview, credential,
  backup and notification-consent boundaries are retained.
