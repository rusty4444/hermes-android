# Hermes Android 3.1.0

Version **3.1.0+3013** is the stable promotion of the 3.1 release candidates.
It adds opt-in foreground hands-free voice, a Settings switch to hide the voice
controls, `paste.txt` attachments for long pastes, and stricter stock-idle
settlement. The production package, signing identity, gateway requirements and
saved conversation data remain unchanged.

## Changes since 3.0.6

- **Opt-in foreground hands-free voice** (#142, #216): explicit-start Android
  “Hey Hermes” wake detection, one recognised prompt through normal chat
  admission, that turn's spoken reply through the selected voice/rate, and a
  configurable 0–30 second follow-up window (default 10). The mode is off by
  default; navigation, account changes, backgrounding, permission loss and
  manual interaction revoke consent before asynchronous work continues.
  Reopening never restarts the microphone. Wake detection runs locally on the
  CPU with bundled, hash-checked sherpa-onnx 2.0.1 and the GigaSpeech 3.3M
  int8 model; no wake PCM is stored or uploaded. Wake is offline, but Android
  speech recognition, the selected reply voice and the gateway may use
  networks.
- **Settings → Voice → Hands-free voice switch** (#227, #228): turns the
  feature off entirely per device — the start/stop control and in-chat voice
  controls disappear and a running session stops immediately. Re-enabling
  restores the control surface but never restarts capture.
- **A shared, joinable native capture owner** for manual dictation and
  hands-free input with generation/request/sequence fences; decode and worker
  joins stay off the UI thread. Manual dictation remains draft-only.
- **Long pastes attach as `paste.txt`** in Remote Gateway chats when the
  committed insertion exceeds 3,000 UTF-16 code units (matching the Desktop
  threshold). Names are collision-safe, exact pasted UTF-8 is preserved, and
  nothing uploads before Send. Short pastes and legacy REST stay inline (#212).
- **Stricter stock-idle settlement** (#221): an idle stock turn settles as
  successful only on an owned completion receipt whose payload matches the
  exact text streamed for the current turn. A rejected foreign completion can
  no longer manufacture the next completion's evidence, and an owned receipt
  without a durable response-row floor releases admission as unknown instead
  of leaving the chat busy indefinitely.

## Upgrading

Export an encrypted configuration backup and keep its password safe. Install
the matching production-signed APK over the existing app without uninstalling
or clearing app data. Package `com.hermesagent.hermes_android` and the
established production signing certificate remain unchanged.

Base code `3013` yields `30131` for ARMv7, `30132` for ARM64 and `30133` for
x86_64, above every 3.1 RC and every 3.0.x split. Debug builds use the separate
`.dev` package and are not production upgrades.

## Compatibility and delivery limits

- No host patch, gateway restart, model-routing change or new server setting is
  required. Existing optional mobile-push companion prerequisites still apply.
- Hands-free mode is foreground-only: no background microphone service,
  always-on hardware hotword or same-breath pre-roll. Say the phrase, wait for
  “Ready — speak now”, then speak. It requires an idle connected chat, an
  empty draft, no attachments and spoken replies enabled.
- Physical-device acceptance remains explicit and unverified: microphone →
  STT → gateway → TTS behaviour, Android 14–16 permission/privacy/lock
  scenarios, human accents and noise, Bluetooth/car mode, battery/thermal and
  latency measurements, source-built AAR/F-Droid acceptance and physical
  16 KB-page launch. The pinned engine's synthetic wake-detection checks
  measure engine compatibility, not human microphone accuracy or field false
  accepts.
- Clipboard-paste detection is a bulk-insertion heuristic: physical-phone
  clipboard testing has not been performed, and an indistinguishable keyboard
  snippet/dictation commit can also become an attachment.
