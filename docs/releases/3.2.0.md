# Hermes Android 3.2.0

## Status and identity

Stable promotion preparation of the user-approved, tested RC.5 application at
`82a172e19fe4f0e4bc03298c129aa52a84efe1dd`. This document covers **all changes
since the last published stable 3.1.7**, whose annotated tag resolves to
`cbbb0e4df375e224d754ee9fd8615f5db47f0a05`, not merely the RC.4 → RC.5 delta.
Application code, assets, Android configuration and dependency versions are
unchanged from RC.5; only release identity, validation and documentation change.

**3.2.0 publication is pending.** The README's 3.2.0 download URLs are publication
targets, not evidence of available stable APKs. At preparation time, the latest
published stable is 3.1.7, followed by 3.1.0 and 3.0.6. Tags 3.1.1–3.1.6 are
source-only preparations, not published APK releases. RC.1–RC.5 are published
prereleases; the older RC documents record their preparation-time state and
must not be read as current publication or feature-integration claims.

- Identity: `3.2.0+3026`; intended tag: exactly `v3.2.0`.
- Expected split codes: ARMv7 `30261`, ARM64 `30262`, x86_64 `30263`.
  Every split exceeds RC.5's highest published split `30253`.
- Production package: `com.hermesagent.hermes_android`; accepted upgrade floor
  remains `2127`. Debug `.dev` APKs are not production upgrades.

  `475baf431b16d050c8f658ac838783b273f7c10bba06ed1d16bb0a4239f592fb`.

## Usage, Portal and provider sign-in

- **More → Usage** brings together Nous Portal, OpenRouter, OpenAI, Claude and
  DeepSeek. Provider entries remain discoverable even when model discovery is
  empty, partial or unavailable; OpenAI uses the canonical provider identity.
- Nous Portal shows gateway status and profile-wide recorded usage/model
  analytics. Provider screens filter Hermes-recorded activity, including retired
  models. Neither is a provider balance, pricing catalogue or billing statement.
- Host-reported Codex and Claude OAuth account allowances are separate from paid
  OpenAI/Claude API usage. Show only reported five-hour/session and weekly windows,
  remaining percentages and reset timestamps. Missing values stay unavailable,
  accounts are not averaged, and unknown/model-specific window labels retain
  their scope. There is no invented daily quota, token budget or entitlement.
  Allowance and recorded-analytics reads have independent loading/retry paths.
- **More → Usage → Provider sign-in** and **Settings → Provider sign-in** use
  Dashboard device-code login for Nous, OpenAI Codex, MiniMax and xAI. Anthropic
  remains external-only; OpenRouter is absent from this audited OAuth catalogue.
  API-server and Desktop RPC transports do not implement this login flow.
- Only explicit taps open validated HTTPS provider pages externally. Codes stay
  transient in route memory and provider tokens stay on the host. Saved origin,
  prefix, authentication, profile and mTLS boundaries survive discovery, start,
  poll, cancellation and catalogue readback; authenticated redirects are rejected.
- Approval says **Approval received; account verification unavailable**, not
  **Signed in as**. Historical approved-session identity cannot verify the current
  host account. Approval refreshes only the same-profile OAuth catalogue, not
  generic model/analytics data. If catalogue loading fails, close and reopen this
  screen; it has no in-screen catalogue retry. Nous free-tier replacement may
  change host defaults; the app warns rather than promising token-only effects.
- OAuth and quota copy is translated across all 11 shipped ARB locales, including
  regional variants; the earlier RC.2 English-fallback description is historical.

See [provider usage](../provider-usage.md), [OAuth safety](../provider-oauth.md)
and [account-readback limits](../provider-oauth-readback-verification.md).

## Profile and cron model management

- **More → Agent → Model** now owns the profile default and auxiliary task
  assignments formerly under Settings. Choose and explicitly save a supported
  provider/model; accepted writes require exact readback. Existing per-chat
  overrides remain unchanged. Auxiliary task IDs supplied by newer hosts are
  retained, as are unknown current models and server expensive-model guards.
- Main-model editing requires matching host route metadata from
  `/api/providers/custom-endpoints`, not endpoint-free `/api/model/info` or a
  flattened config response. Missing, malformed or mismatched metadata disables
  main editing until Refresh; independent auxiliary controls remain usable.
- Recognised exact canonical provider/URL pairs are standard routes even when
  the host persists a nonempty URL. Active named custom routes take precedence;
  custom, local, overridden and unrecognised routes remain read-only. Catalogue
  `api_url` fields, hostname similarity or URL suffixes cannot establish safety.
  Readback repeats the route-safety check before reporting success.
- **Crons → Edit → Model** pins a provider/model for that job only. **Follow
  default** clears `model`, `provider` and `base_url`; selecting a discovered
  model also clears an old endpoint. Unchanged routes are omitted from updates.
  Custom/retired and endpoint-only pins remain visible and are not silently
  normalised. Endpoint editing is not offered; script-only mode retains but
  cannot change its pin. Confirmed saves require exact-job route readback.
- Discovery, writes and readback preserve selected-profile authority and the
  normalised saved Dashboard origin, prefix, authentication and mTLS identity.
  Explicit profiles never fall back to the launch profile. Late responses after
  connection replacement/disposal cannot confirm a stale save. Missing local TLS
  identity is retryable rather than a construction crash or unauthenticated retry.

See [model management](../model-management.md) and
[per-cron selection](../cron-model-selection.md).

## Chat, approval, discovery and accessibility fixes

- Searchable command palette for copy latest code, refresh, export, rename and
  archive actions. Code copying follows the latest visible assistant code block
  across received/saved handoff, not a stale reply or hidden background report.
- Composer code/bold/italic helpers and compact/200%-text/keyboard layouts remain
  usable. The new-chat sheet scrolls so every mode stays reachable on compact
  large-text screens.
- REST run approvals preserve canonical prompt identity and execution generation,
  reject malformed/stale authority rather than downgrading to legacy controls,
  and use the saved profile. Back cannot dismiss an approval while a response is
  submitting, preventing a concurrent denial.
- Untitled cron shells are hidden only with an explicit valid integer zero count
  and no raw/display preview. Unknown-count, titled and content-bearing rows
  remain available; this is presentation filtering, never server deletion.
- Follow-up LAN repairs bound probing/cancellation, validate health/model response
  shapes and retain the verified HTTPS scheme, port and scoped IPv6 identity.
  LAN discovery itself already shipped in 3.1.7; it is not new in 3.2.0.
- Feature clients consistently use the normalised Dashboard origin instead of
  accidentally routing requests through a different service/port.

The audited Git range also contains merged ancestor commits for batch
clarification parsing and collapsed Android-context notices, but their affected
model/presentation files are unchanged against the 3.1.7 tree. They are not
advertised as new stable-to-stable capabilities.

## Compatibility, evidence and remaining publication gates

Export an encrypted configuration backup before installing a matching
production-signed APK. Do not uninstall or clear app data. The expected codes
permit in-place upgrades from 3.1.7 and every 3.2 RC once signing is verified.

An APK update does not install host endpoints or the optional mobile-push server
companion. The existing exact-host boundary remains: shared-dashboard secondary
profiles lack verified identity-forwarding support; use a separately launched,
explicitly enabled dashboard per profile for that companion path. No push ACL,
consent or permission check was weakened. See
[exact-host compatibility](../mobile-push-exact-host-compatibility.md).
Provider fixtures and model-route producer snapshots do not establish real-account
acceptance or permission to mutate live host configuration. RC phone approval is
not universal device, microphone, notification-delivery or host compatibility.

The release owner still must integrate/review this metadata commit, pass CI on
the exact final main commit, create the immutable stable tag, build all three
production-signed splits, and verify package/version/code/ABI/signer/notices and
exact-commit source/relink materials. One create-only publisher must publish the
stable release (not draft or prerelease), followed by downloading and reverifying
all published assets, checksums and source materials. Prior RC validation does
not verify a stable CI rebuild. No remote merge, push, tag, GitHub release,
GitLab or F-Droid update is performed by this preparation.
