## Included changes

- **Nous Portal (#235):** More opens read-only gateway Portal status plus
  profile-wide recorded usage and model analytics. Analytics cover all providers,
  not a Portal-only bill; no balance, model pricing or subscription is invented.
- **OpenRouter (#237) and provider settings (#238):** lazy, retriable catalogue
  discovery supplies provider entries for OpenRouter, ChatGPT, Claude and DeepSeek.
  Their screens filter Hermes-recorded model usage by provider, including models
  no longer in the catalogue. They do not log into provider accounts, collect API
  keys or fetch provider-account balances.
- **Auxiliary models (#238):** Settings reads dashboard-owned task assignments
  and supported model options. Explicit Save checks server acceptance and reads
  the assignment back. Busy-state serialization and expensive-model guards are
  retained. Custom/local endpoint assignments stay read-only rather than being
  silently cleared or replaced.
- **Command palette/composer (#239):** command filtering and compact/large-text
  layouts remain usable; code copying follows the latest visible assistant reply
  across received-to-history handoff rather than a stale earlier reply.
- **Cron filtering (#240):** presentation suppresses untitled cron shells only
  with a valid explicit zero message count and no raw/display preview. Unknown
  counts, titles and content-bearing conversations remain available. Filtering
  does not delete server history or alter human conversation eligibility.
- **LAN follow-up:** bounded probing and cancellation, validated API/model response
  shapes, and preservation of verified HTTPS/port and scoped IPv6 identity. The
  scoped-address fixture is portable; local macOS tests are not Linux execution.

Saved dashboard origin/prefix, authentication, selected-profile routing and mTLS
remain in force. TLS construction failures have safe retry without a weaker
unauthenticated fallback. Late responses cannot replace a newer connection's
screen. Original contributor histories and adverse-order regressions are retained.

## Compatibility and evidence boundary

These capabilities depend on the host exposing the corresponding endpoints. An
APK update does not install or configure Hermes or the optional mobile-push
companion. Provider analytics are recorded host usage, not live provider billing.
Auxiliary changes affect server configuration and require explicit user action.

Validation receipts belong to the release owner's external evidence directory,
pinned to the exact frozen commit/tree. A local debug compile, synthetic router
smoke or passing component suite is not evidence of production signing, Linux
runner success, real provider accounts, installed-phone behaviour or notification
delivery. No tag, release, installation, signing or live backend mutation is part
of this local preparation. The debug build uses the separate `.dev` application
identity and must not be used to prove production in-place upgrades.
