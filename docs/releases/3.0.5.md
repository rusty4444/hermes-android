# Hermes Android 3.0.5

Version **3.0.5+3009** improves scheduled-task presentation and approval-dialog
navigation. The production package, signing identity, gateway requirements and
saved conversation data remain unchanged.

## Changes since 3.0.4

- Recognised scheduled-job setup, including embedded skill instructions, appears
  as a neutral, read-only **Background task** card. It starts collapsed in
  Verbose Mode and is hidden in conversation-only mode. Ordinary human skill
  invocations, raw roles/content, canonical request history and retry ownership
  retain their existing behaviour (#218).
- Answering an approval dismisses only its originating dialog. If normal turn
  cleanup already removed that dialog, the response cannot also pop the chat.
  If a newer prompt covers it, the newer route stays open (#220).

## Upgrading

Export an encrypted configuration backup and keep its password safe. Install
the matching production-signed APK over the existing app without uninstalling
or clearing app data. Package `com.hermesagent.hermes_android` and the established
production signing certificate remain unchanged.

Base code `3009` yields `30091` for ARMv7, `30092` for ARM64 and `30093` for
x86_64, above every 3.0.4 split. Debug builds use the separate `.dev` package and
are not production upgrades.

## Compatibility and delivery limits

- No host patch, gateway restart, model-routing change or new server setting is
  required. Existing optional mobile-push companion prerequisites still apply.
- Cron compatibility is presentation classification, not authenticated provenance.
  Explicit display metadata and available merge witnesses retain precedence.
  A byte-identical human copy without distinguishing metadata can remain
  ambiguous; classification does not alter the underlying stored message.
- This release does not include the blocked long-paste or stock-idle settlement
  PRs. It adds no WebSocket execution-idempotency guarantee and never treats
  delivery uncertainty as permission to resend.
- Automated widget, owner, full-suite and CI gates do not certify physical-phone
  acceptance or universal gateway compatibility. Existing preview, credential,
  backup and notification-consent boundaries are retained.
