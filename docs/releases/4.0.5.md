# Ares 4.0.5

Stable patch release `4.0.5+3062`. ABI split codes `30621` (armeabi-v7a),
`30622` (arm64-v8a) and `30623` (x86_64), each above the highest published
4.0.4 split (`30613`). The production package `com.hermesagent.hermes_android`
and signing certificate are unchanged; install over the existing app.

Covers all changes since 4.0.4.

## Fixed

### NextGen history paging survives a running turn (#275)

NextGen pages older history with an offset counted from the newest stored row.
When a running turn stored new rows while the reader was scrolled back, the
newest end moved under that offset, the next page came back holding only rows
already on screen, and paging switched off until a reconnect resynced the chat.

An all-known full page now moves a floor past that window instead of ending
paging, and any page with new rows resets the floor. Rows already shown are
dropped before the page is trimmed to its first prompt, so the floor moves only
past a page that held nothing new, and the unseen tail of a long, tool-heavy
turn next to it is kept.

Contributed by [@Thaeland](https://github.com/Thaeland). Known limits: after a
burst of growth, paging can fetch rows that are already shown, sometimes more
than once, before reaching new ones (tracked in #280). Rows stored by a live
turn can still briefly reappear as older items until the next resync, as in
4.0.4.

### Dashboard sign-in through the gateway Webapp (#282, fixes #281)

The dashboard served by `hermes webapp` suffixes every sign-in cookie name with
a per-gateway id (`__Host-hermes_session_at_<gateway>`) and, behind its sign-in
gate, treats a session as signed out unless the matching
`hermes_webapp_signin_<gateway>` binding cookie comes with it. Ares only
recognised the bare session cookie name, so password sign-in succeeded and
every later request failed.

`DashboardClient` now matches each cookie under its real name, with the
optional `__Host-`/`__Secure-` prefix and gateway suffix, and sends the binding
cookie beside the session cookie when the login set one. The standalone
`hermes dashboard` keeps its bare names and no binding, so its requests are
unchanged.

Contributed by [@manuelanguitatrejo](https://github.com/manuelanguitatrejo).

## Install

Download the APK for your device from the release assets and install over the
existing app; do not uninstall or clear app data.

## Verification

- The full Flutter test suite passes, including regression tests for paging
  after page-aligned growth, growth beside a tool-heavy turn longer than a page,
  a gateway-suffixed `__Host-` session cookie, and the sign-in binding cookie on
  both `/api/` requests and `/api/auth/ws-ticket`.
- Release APKs are production-signed and verified against the established
  signer SHA-256 `475baf43…f592fb`.

## Not verified

- Live device sign-in against a running gateway Webapp, and paging during a
  live turn on a physical phone, beyond automated tests.
