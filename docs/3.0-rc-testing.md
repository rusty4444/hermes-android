# Hermes Android 3.0 release-candidate testing

This guide records the **historical 3.0 release-candidate** testing procedure. RC3 was promoted to [3.0.0](releases/3.0.0.md) with a higher upgrade-safe build code. For the current stable release, see the [README](../README.md#current-release). Do not install an older RC to obtain the stable release. The APK does not install, upgrade or reconfigure a live gateway or mobile-push companion.

## Install and rollback

- Release identity: `3.0.0-rc.1+3000`, tag `v3.0.0-rc.1`.
- Most current phones use `app-arm64-v8a-release.apk`. The other APKs are for older 32-bit ARM devices (`armeabi-v7a`) and x86_64 Android devices/emulators.
- Production-signed APKs use the existing `com.hermesagent.hermes_android` package and upgrade the stable app in place. Export an encrypted configuration backup first and retain its password securely.
- Split version codes are `30001`, `30002` and `30003`. An older stable APK has a lower version code and cannot normally be installed as a downgrade. Returning to it can require uninstalling the RC, which removes app-local data; retain the backup. A subsequent approved stable 3.0 build must use a higher build code than this RC.
- Download only from the GitHub prerelease. Check `SHA256SUMS` if transferring the APK between devices.

## Phone test checklist

1. **Upgrade and accounts:** existing saved connections, API/dashboard authentication, selected profile, prefixes, local pins, Quick Chat expiry and preferences survive installation. Switch between accounts and confirm no conversation, notification or approval appears under the wrong account.
2. **Navigation:** Chats is the default; Crons, Projects, Activity and More remain usable. Cron conversations stay outside human Chats search/filters. Projects retain correct folder membership and counts. More → Memory continues to display saved user/agent facts, not configuration.
3. **Chat and drafts:** send a message in a new chat and an existing chat through each configured transport. Start a long tool-heavy turn, type the next draft while it runs, leave the route, reopen via the canonical conversation, and confirm the draft and received output survive. Do not resubmit an uncertain prompt merely because the socket disconnected.
4. **Background and recovery:** start concurrent chats; cover the app, lock the phone, change network, reopen and verify no duplicate prompt, premature success or permanently disabled controls. Check interrupted/failed outcomes remain distinct from success. OS Force stop and vendor battery restrictions can prevent background delivery.
5. **Approvals and notifications:** grant/deny OS notification permission, change it in Android settings, and reopen. Test a notification tap while paused, after switching accounts and after changing credentials. Stale or unscoped sensitive actions must fail closed; ordinary safe chat navigation should still work.
6. **Lists and archiving:** refresh with slow or unavailable dashboard access; known rows remain visible and incomplete views are labelled. Rename from Search/Unassigned, return to Chats, then reopen. Archive/unarchive ordinary and expired Quick Chats and confirm the result persists after an app restart. Verify older local pins and compressed conversations navigate to the current conversation.
7. **Themes:** try all ten palettes in light/dark/system appearance, including before connecting. Change appearance, dismiss the sheet quickly and confirm the surviving app updates. Check chat, dialogs, keyboard composer, task details, large text and narrow layouts for contrast/overflow.
8. **Attachments and Assets:** generate an image, PDF, text/CSV and another binary file. Explicit `MEDIA:` deliveries, filesystem Markdown links and recognised successful image-tool results should appear in the timeline and More → Assets, even with verbose tools hidden. Test image zoom, Android PDF paging, selectable inert text and the unsupported-format fallback. Use Download from both card and popup to save the exact bytes; cancel must not report success. Test Share separately, missing/denied files and files over 25 MiB. Code/quoted examples must not appear. Reopen the chat and Assets, then test search, filters, more/older scans and opening/returning from the source chat. The browser is partial discovery, not a complete filesystem or attachment catalogue.
9. **mTLS (if used):** import a test PEM pair or P12/PFX identity, then test listing, chat/history, search, task history, downloads and dashboard WebSocket access against the same certificate-enforcing origin. Replace/remove the identity, restart and confirm the old identity is no longer used. Check encrypted backup/restore and cancellation cleanup. File import is not Android KeyChain/non-exportable-key support; private-CA trust on a physical device needs separate validation.
10. **Optional automatic push:** enable only with a compatible, authenticated, operator-authorised paired mobile-push companion. Missing/outdated companions must give an actionable failure without silently broadening consent. Test Google Play Services or an external UnifiedPush distributor as appropriate, account edits/removal, endpoint renewal, reboot, Doze and OS process death. This RC does not claim those device behaviours have already passed.

## Report a failure

Record the installed version from About, Android version/device, transport and exact origin/profile (no passwords or tokens), timestamp, expected/actual result and reproduction steps. Distinguish app route removal, OS process death and Android Force stop. Redact private chat content from screenshots and logs.

## Stable promotion gate

Do not mark the prerelease stable, change the latest-stable release, submit this RC to GitLab/F-Droid, or retag the candidate after publication. After testing and approval, fix forward with a fresh version/build code and publish a new immutable stable tag.
